# Шаблон промпта для генерации интерфейса Scope Creep Guard

## Промпт

Создай интерактивный интерфейс рабочего веб-прототипа **Scope Creep Guard**.

### О продукте

Scope Creep Guard помогает фрилансеру определить, входит ли новый запрос клиента в согласованный объём работ. Пользователь сохраняет исходный scope проекта, вставляет новый запрос и получает:

1. вердикт `In scope`, `Borderline` или `Out of scope`;
2. короткое объяснение со ссылками на соответствующие пункты scope;
3. профессиональный ответ клиенту на английском языке;
4. для `Out of scope` — черновик Change Order.

Главная ценность продукта: за время менее двух минут помочь пользователю обнаружить неоплачиваемую дополнительную работу и уверенно ответить клиенту.

### Целевая аудитория

Основной пользователь — индивидуальный фрилансер в разработке, дизайне или маркетинге, работающий с зарубежными клиентами. Английский может быть для него неродным. Пользователь ценит ясность, скорость и профессиональный тон, но не обязан разбираться в юридических терминах.

### Формат прототипа

- Тип: desktop-first responsive web application.
- Язык интерфейса: [английский / русский].
- Технологии: [React + TypeScript + Tailwind CSS].
- Формат результата: [готовая страница / набор компонентов / работающий прототип].
- Используй тестовые данные без подключения реального backend и LLM.
- Не создавай лендинг, маркетинговый сайт, биллинг или административную панель.

### Основной пользовательский сценарий

Пользователь должен без инструкции пройти следующий путь:

1. Создать или выбрать проект.
2. Добавить исходный scope обычным текстом.
3. Вставить новый запрос клиента.
4. Нажать `Check scope`.
5. Увидеть вердикт, уровень уверенности и понятное объяснение.
6. Просмотреть и отредактировать готовый ответ клиенту.
7. Скопировать ответ.
8. При результате `Out of scope` открыть и отредактировать Change Order.

Сделай этот сценарий главным визуальным маршрутом. Убери всё, что не помогает его пройти.

### Структура интерфейса

Создай следующие экраны или состояния:

#### 1. Projects

- компактный список проектов;
- название клиента и проекта;
- дата последней проверки;
- кнопка `New project`;
- понятное пустое состояние для первого проекта.

#### 2. New project

- название проекта;
- имя клиента — необязательное поле;
- отрасль: Development, Design или Marketing;
- большое поле для исходного scope;
- подсказка, что можно вставить текст из договора, proposal или SOW;
- кнопка `Save project`.

#### 3. Scope check — главное рабочее пространство

Раздели экран на две логические зоны:

- слева: выбранный проект, краткий исходный scope и поле `New client request`;
- справа: результат анализа.

До запуска анализа справа покажи спокойное пустое состояние. Во время анализа покажи заметный, но ненавязчивый loading state.

#### 4. Analysis result

В верхней части результата покажи один хорошо различимый статус:

- `In scope` — зелёный;
- `Borderline` — янтарный;
- `Out of scope` — красный или коралловый.

Цвет не должен быть единственным способом различить статусы: добавь текст и иконку.

Под статусом покажи:

- краткий вывод одним-двумя предложениями;
- уровень уверенности;
- блок `Why this verdict`;
- цитаты или выдержки из исходного scope, на которых основан вывод;
- предупреждение, что результат необходимо проверить перед отправкой клиенту.

#### 5. Client reply

- редактируемое поле с профессиональным ответом на английском;
- переключатель тона: `Warm`, `Neutral`, `Firm`;
- кнопки `Copy reply` и `Regenerate`;
- явное подтверждение успешного копирования;
- никаких функций автоматической отправки.

#### 6. Change Order

Показывай этот блок только для `Out of scope` или по явному действию пользователя.

Поля:

- описание дополнительной работы;
- влияние на сроки;
- дополнительная стоимость;
- примечание;
- кнопки `Copy` и `[Download draft]`.

Добавь пометку, что документ является черновиком, а не юридической консультацией.

#### 7. History

- простой список предыдущих проверок выбранного проекта;
- дата, краткий текст запроса и вердикт;
- без сложных фильтров, поиска и аналитики.

### Обязательные состояния

Покажи не только идеальный сценарий, но и следующие состояния:

- новый пользователь без проектов;
- проект без сохранённого scope;
- пустой клиентский запрос;
- анализ выполняется;
- `In scope`;
- `Borderline`;
- `Out of scope`;
- ошибка анализа с возможностью повторить;
- слишком короткий или неоднозначный scope;
- ответ успешно скопирован.

### Визуальное направление

Интерфейс должен ощущаться как спокойный профессиональный рабочий инструмент, который помогает принять потенциально конфликтное решение.

- Стиль: [сдержанный SaaS / редактор документов / современный productivity tool].
- Характер: надёжный, ясный, тактичный, без агрессивной «юридической» эстетики.
- Плотность: средняя; достаточно воздуха, но без огромных пустых областей.
- Цветовая база: нейтральная, с отдельными цветами для трёх вердиктов.
- Типографика: хорошо читаемая, с ясной иерархией.
- Используй карточки и разделители только там, где они помогают понять структуру.
- Не используй градиентные hero-блоки, декоративные графики, стеклянные панели, лишние иллюстрации и чрезмерно скруглённые элементы.
- Не превращай каждый текст в отдельную карточку.
- Основное действие `Check scope` должно быть очевидным.

### UX-требования

- Главный сценарий должен занимать минимум действий.
- Не скрывай причину вердикта во всплывающем окне.
- Сохраняй введённый текст при ошибках.
- Не выдавай результат AI за юридическое или окончательное решение.
- Для `Borderline` предложи пользователю уточнить scope или задать клиенту вопрос.
- Пользователь всегда редактирует и подтверждает сообщение перед отправкой.
- Все элементы должны быть доступны с клавиатуры.
- Соблюдай достаточный цветовой контраст.
- Интерфейс должен корректно работать на ширине от 1024 px; для мобильной ширины достаточно читаемого последовательного расположения блоков.

### Тестовые данные

Используй реалистичный пример:

- Project: `Acme website redesign`;
- Industry: `Design`;
- Scope: дизайн пяти ключевых страниц, один раунд правок, без разработки и копирайтинга;
- Client request: клиент просит добавить ещё три страницы, подготовить мобильные варианты и провести второй раунд правок;
- Expected verdict: `Out of scope`;
- Reply: вежливо объясняет, что дополнительные страницы и второй раунд правок не входят в исходный scope, и предлагает согласовать стоимость и срок.

Также подготовь данные для состояний `In scope` и `Borderline`.

### Ожидаемый результат

Сначала создай главное рабочее пространство Scope Check и полностью реализуй основной сценарий. После этого добавь Projects, New Project и History.

Результат должен выглядеть как прототип, который можно показать 5–10 фрилансерам и проверить, понимают ли они вердикт и готовы ли использовать предложенный ответ клиенту.

Не добавляй функции, которых нет в этом описании. Если какое-либо решение не определено, выбери самый простой вариант и пометь допущение в конце результата.
