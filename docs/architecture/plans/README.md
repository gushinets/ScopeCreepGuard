# Implementation plans

Store all future implementation plans in this directory. Use stable names such
as `YYYY-MM-DD-any-NNN-descriptive-name.md`; keep `docs/plans.md` as historical
context rather than creating a conflicting `docs/plans/` directory.

Each plan records the issue identifier/title, base and branch, approved checkout
workflow, scope/exclusions, ordered steps, verification evidence, limitations
and follow-up ownership. Treat a plan as the implementation record, with
`../ownership.md` remaining the high-level architecture source of truth.
